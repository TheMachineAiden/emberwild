# Implementation review

Rules and save validation remain in `engine.js`; named turn snapshots feed `battle-sequence.js`, which owns timing and overlap rejection. A turn is resolved once on a copy, so presenting successive effects cannot reroll damage, consume an item twice or save an intermediate battle state. Controls stay locked through the reply/faint/result phases. Tests cover ordered HP changes, invalid actions, capture outcomes, forced replacement, no reply after a defeated opponent and cancellation of stale presentation frames.

`travel.js` plans the existing tile rule once and commits only at arrival. Rendering interpolates avatar/camera coordinates; collision, map exits and encounter rolls remain logical-tile operations. Held inputs clear at encounter entry, blur and hidden state. Letter keys are normalized for both press and release, preventing a Shift/case change from leaving a direction held. Presenter tests cover interpolation, release, turn priority, obstacles, exits, encounter entry and case-independent release. Ordinary browser checks cover pointer holding and normal keys; sustained physical keyboard hold remains a coverage limit.

Audio retains editable scores and routes each cue through a small gain bus. Cue replacement retires the old voices after a short fade; same-cue renders preserve the existing schedule. Lifecycle tests cover context startup, replacement, hidden/resumed state, mute cleanup and gain disconnection. Browser observation verifies gesture-start, context reuse and transitions; it is not a listening verdict.

No material unresolved maintainability defect was found in these changed boundaries. Rendering remains a straightforward DOM/canvas module rather than a new engine. The static build allowlists runtime files and records the exact clean checkout revision. Save compatibility, free recovery and level caps remain covered by existing rule checks. Rendered review and publication decisions are separate from these code findings.
